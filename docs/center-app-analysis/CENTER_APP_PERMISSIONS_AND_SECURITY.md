# الصلاحيات والأمان — تطبيق المراكز

## 1. نموذج الهوية المستهدف للموبايل

| العنصر | القيمة |
|---|---|
| Actor | `CenterUser` |
| Guard/Panel | `center` |
| Token | `PanelApiToken` morph على CenterUser، `panel=center` |
| Tenant key | `center_users.center_id` فقط من السجل المصادق — ليس من الطلب |

**ممنوع:** استخدام توكن عميل `/api/v1` للوصول لبيانات تشغيل المركز.

---

## 2. ما هو مطبّق اليوم (ويب)

| آلية | الوضع |
|---|---|
| Session `auth:center` | نعم |
| `EnsureCenter` (active + center_id) | نعم |
| `forCenter($id)` على Booking/Operation | نعم |
| `abort_unless(model.center_id === Tenant::centerId())` عند التحديث | نعم في Controllers الحالية |
| DestinationResolver للإشعارات | يتحقق أن الحجز/العملية لنفس المركز |
| أدوار دقيقة داخل المركز (manager vs staff) | **لا** على `center_users` |
| API Bearer للمركز | **لا** |

## 3. تهديدات يجب إغلاقها في API الجديد

### 3.1 IDOR
- أي `{booking|operation|customer|complaint}` يُجلب بعد فلترة `center_id`.
- الاستجابة 404 عند عدم التملك (لا 403 يكشف الوجود).

### 3.2 التلاعب بـ center_id
- تجاهل أي `center_id` في body/query للكتابة.
- Services تستقبل CenterUser وتشتق المركز داخلياً.

### 3.3 Lookup QR/NFC/Plate
- الإرجاع يجب أن يكون محدوداً: بيانات لازمة للخدمة فقط.
- لا تُرجع محفظة كاملة أو بيانات حساسة لعملاء مراكز أخرى دون حاجة.
- Rate limit صارم على `/operations/lookup` لمنع enumerations.

### 3.4 إنشاء العملية والدفع
- خصم المحفظة/الاشتراك في Transaction DB واحدة.
- منع إنشاء عملية مكررة لنفس المركبة بحالة `in_progress` في نفس المركز.
- التحقق من أن `service_id` ضمن `center_service` ومتاح.

### 3.5 الصور
- رفع عبر endpoint مصادق؛ تخزين خارج web root العام إن أمكن؛ روابط مؤقتة أو محمية.
- ربط الصورة بـ operation يملكها المركز فقط.

### 3.6 كود تحقق الشركات
- لا يُخزَّن نصاً صريحاً إن كان PIN دائماً (hash).
- قفل محاولات فاشلة.

### 3.7 الإشعارات
- نفس عزل panel center؛ deep links داخل التطبيق فقط بعد التحقق من المرجع.

## 5. فصل الأنظمة

| نظام | لا يملك |
|---|---|
| Center App | إدارة كل المراكز، أسعار التعاقد، باقات النظام، محفظة عميل للإيداع |
| Admin | تشغيل QR الميداني (اختياري) |
| User App | قبول حجوزات المركز أو إنشاء عمليات مركز |
| Center Web | نفس بيانات المجال؛ جلسة مختلفة؛ ليس بديلاً أمنياً عن API |

---

## 6. متطلبات أمان التطبيق (Flutter)
- تخزين التوكن في Secure Storage
- Certificate pinning اختياري لاحقاً
- لا تخزين PINs/QR خام دون حاجة
- إخفاء شاشات حسب role من السيرفر وليس فقط UI
- Logout يبطل التوكن سيرفر-سايد

---

## 7. اختبارات أمان مطلوبة عند التنفيذ
1. Center A لا يقرأ/يحدّث حجز Center B
2. Lookup لمركبة ثم إنشاء عملية يفرض خدمات مركز A فقط
3. توكن عميل مرفوض على `/api/center/v1`
4. حساب موقوف يُرفض بعد الإصدار أيضاً (فحص status في middleware)
5. رفع صورة لعملية مركز آخر → 404
6. Rate limit login + lookup

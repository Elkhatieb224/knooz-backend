# المواصفات الوظيفية — تطبيق المراكز (Center App)

## 1. الجهات المستخدمة
| الدور | الوصف | مصدر الحساب |
|---|---|---|
| Center Manager | مدير المركز | `center_users` + تعيين من Admin |
| Center Staff | موظف مركز (إن وُجدت أدوار فرعية) | نفس الجدول/صلاحيات |

**ليس** مستخدماً نهائياً (`customers`) ولا Admin ولا Company user.

## 2. السيناريوهات الأساسية

### S1 — تسجيل الدخول
1. يدخل البريد/الجوال وكلمة المرور.
2. Backend يتحقق من `center_users` وأن المركز مفعّل.
3. يُصدر Token (مطلوب API للموبايل — حالياً الجلسة ويب فقط).
4. ينتقل للوحة الرئيسية مع بيانات المركز.

### S2 — استقبال طلب حجز وارد
1. عميل (User App) ينشئ حجزاً على المركز.
2. يظهر الطلب في Dashboard / Incoming.
3. الموظف يقبل أو يرفض.
4. عند القبول يمكن بدء الخدمة لاحقاً أو فوراً.

### S3 — بدء عملية عبر QR
1. من الرئيسية أو العمليات → مسح QR.
2. الرمز يحلّل إلى مركبة/عميل/حجز.
3. تُعرض بيانات المركبة والخدمات المتاحة.
4. اختيار خدمات + تأكيد → خصم من المحفظة/طريقة الدفع → حالة In Progress.
5. إنهاء العملية وتسجيل النتيجة.

### S4 — NFC
مماثل لـ QR مع مصدر تعريف مختلف (بطاقة/وسم).

### S5 — إدخال لوحة يدوي
1. إدخال رقم اللوحة.
2. بحث ضمن مركبات النظام المرتبطة بالمركز/العملاء.
3. إن وُجدت → تفاصيل العملية؛ وإلا Empty/Error.

### S6 — مركبة شركة / تحقق هوية
حسب `info.md` والتصميم: قد يُطلب كلمة مرور/تحقق إضافي قبل الخدمة على مركبات الشركات.

### S7 — التقارير
عرض KPIs: عمليات اليوم، إيرادات، معدلات قبول، أداء موظفين (إن وُجدت).

### S8 — العملاء
قائمة العملاء الذين تعاملوا مع المركز + تاريخ العمليات.

### S9 — الشكاوى
عرض/إنشاء شكاوى مرتبطة بعمليات المركز.

### S10 — الإشعارات
إشعارات حجوزات جديدة، تذكيرات، تحديثات حالة، رسائل نظام — معزولة لـ Center audience.

### S11 — الإعدادات/الملف
عرض بيانات الحساب، تغيير كلمة المرور، تفضيلات الإشعارات، اللغة.

## 3. قواعد العمل (Business Rules) — مؤكدة/مستنتجة
| القاعدة | الحالة |
|---|---|
| المركز يرى بياناته فقط | مطلوب أمنياً — يجب فرضه في API |
| الحجوزات مرتبطة بـ `center_id` | موجود في Backend الحجوزات |
| العمليات تستهلك رصيد/محفظة العميل | منطق User App/Wallet موجود جزئياً |
| لا يصل المركز لبيانات مركز آخر | مطلوب — تحقق IDOR في كل endpoint |
| قبول/رفض الحجز يغيّر status | موجود في Center web جزئياً |
| QR/NFC/Manual كلها تؤدي لنفس كيان العملية | مطلوب توحيد في Domain Service |

## 4. حالات الشاشات المشتركة
- **Loading**: جلب Dashboard / قائمة عمليات / مسح
- **Empty**: لا طلبات واردة / لا عمليات / لا نتائج لوحة
- **Error**: فشل شبكة، توكن منتهي، مركبة غير موجودة، رصيد غير كافٍ
- **Success**: قبول طلب، إنهاء عملية، حفظ إعدادات

## 5. ما هو خارج نطاق Center App
- تصفح المراكز كعميل
- محفظة العميل وإيداعها
- لوحة Admin / Company / Center Web كواجهات (قد تشارك المنطق فقط)
